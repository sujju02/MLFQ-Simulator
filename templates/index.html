Multilevel Feedback Queue
CPU Scheduling

MLFQ dynamically adjusts process priorities using multiple queues. CPU-bound processes are gradually demoted to lower queues while I/O-bound processes stay in higher-priority queues. An aging mechanism prevents indefinite starvation.

Three Priority Queues

Q0 (highest) → Q1 → Q2 (lowest/FCFS). New processes always enter Q0.

Time Quantum Demotion

A process exhausting its Q0 (4 ms) quantum is demoted to Q1; from Q1 (8 ms) to Q2.

Preemption

A running low-priority process is immediately preempted when a higher-priority process arrives.

Aging

Processes waiting ≥ aging threshold are promoted to prevent starvation. Reset on each promotion.

📖 Algorithm Details

MLFQ Scheduling Rules

  1. Every new process enters Q0 (highest priority).
  2. Higher-priority queues always execute before lower ones.
  3. If a process exhausts its time quantum it is demoted to the next lower queue.
  4. Processes that complete before the quantum expires are simply removed.
  5. A lower-priority process is preempted when a higher-priority process arrives.
  6. Q2 uses FCFS (no quantum limit unless preempted).
  7. Remaining burst time is preserved across preemptions and demotions.

Aging Policy

Each millisecond a process spends waiting in Q1 or Q2 increments its wait_in_queue counter. When this counter reaches the aging threshold, the process is promoted one level up and its counter is reset to 0. If the promoted process ends up at higher priority than the current running process, an immediate preemption occurs.

Formulae

  • TAT = Completion Time − Arrival Time
  • WT = TAT − Burst Time
  • RT = First CPU Start − Arrival Time
  • CPU Utilization = Busy CPU Time / Total Simulation Time × 100
  • Throughput = Completed Processes / Total Simulation Time
